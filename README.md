# Biblioteca

Sistema de gerenciamento de biblioteca para a disciplina de Linguagem de Programação II.
Base em Java 21, Maven, console e JDBC com H2 embarcado, sem Docker ou servidor externo.

## Executar

Instale um JDK 21 ou superior e configure `JAVA_HOME` para a pasta do JDK.
O Maven Wrapper está incluído; na primeira execução ele baixa Maven e dependências.
Execute os comandos a partir da raiz do projeto.

Se o Maven informar que `JAVA_HOME` não está definido, configure-o na sessão do
PowerShell. Nesta máquina, o JDK 21 está instalado no caminho abaixo; nos outros
computadores, use o caminho da instalação de cada integrante:

```powershell
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\temurin-21.0.11"
```

```powershell
.\mvnw.cmd compile exec:java
```

No Linux/macOS, use `sh ./mvnw` no lugar de `.\mvnw.cmd`.
No IntelliJ, importe o `pom.xml`, selecione JDK 21 e execute `com.imd.Main`.

O console permite navegar pelos módulos e voltar ao menu principal. As operações
estão identificadas como **em desenvolvimento**, para cada integrante conectar
sua implementação. O banco é inicializado ao abrir o programa, mas o console
ainda não consulta nem altera seus dados.

## Banco de dados

A configuração está em `src/main/resources/banco.properties`:

```properties
biblioteca.jdbc.url=jdbc:h2:mem:biblioteca;DB_CLOSE_DELAY=-1
biblioteca.jdbc.usuario=sa
biblioteca.jdbc.senha=
```

O `schema.sql` cria as tabelas vazias ao iniciar o programa. Os dados são descartados
ao encerrar a aplicação. `DB_CLOSE_DELAY=-1` mantém o banco disponível entre a abertura
e o fechamento das conexões durante a mesma execução.

O SQL define as tabelas, IDs automáticos, campos obrigatórios, chaves e relacionamentos.
`GENERATED BY DEFAULT AS IDENTITY` é a sintaxe usada pelo H2 para gerar os IDs.
As validações de negócio, como limites de licenças e impedimento de reservas ou
empréstimos simultâneos, serão implementadas nos módulos Java.

## Estado da base

- Classes, heranças, associações e seis enums do [diagrama](docs/diagrama_biblioteca.png).
- Hierarquias e assinaturas para os polimorfismos de leitores e materiais/empréstimos.
- Modelos com atributos, associações, construtores e getters; métodos de negócio com `TODO`.
- Esquema SQL e fábrica de conexões JDBC.
- Console inicial com navegação e testes da base.

Os modelos estão agrupados em `model.usuario`, `model.acervo`, `model.emprestimo`,
`model.reserva`, `model.sala` e `model.relatorio`.

Login no console, CRUD completo, escrita de empréstimos/reservas, coordenação FIFO,
processamento automático de vencimentos e relatórios são as próximas entregas da equipe.
As camadas de repositório e serviço serão criadas pelos responsáveis conforme
cada módulo for desenvolvido; esta base não antecipa suas interfaces ou implementações.
Os construtores apenas inicializam os dados e as referências, sem executar operações
de negócio ou atualizar objetos relacionados. Métodos abstratos têm apenas a assinatura;
métodos concretos de negócio lançam `UnsupportedOperationException` até a implementação
pelo responsável. Validações, cálculos, autenticação, transições de estado e persistência
serão desenvolvidos nos módulos.

Consulte a [divisão de trabalho](docs/desenvolvimento.md)
antes de iniciar um módulo. Os [requisitos](docs/requisitos.md) e o diagrama continuam
sendo as referências do projeto.

## Verificação

```powershell
.\mvnw.cmd test
```

Os testes verificam a infraestrutura do banco, restrições SQL, rollback e navegação
do console. Os testes de negócio serão desenvolvidos por cada responsável ao implementar
seu módulo.
